# Development

For downloading and using the released app, see [README](README.md).

## Build

This is a clean-room macOS MediaExtension project targeting Apple silicon
(`arm64`) only. Use Xcode with the macOS 26 SDK or newer and run commands from
the repository root. The deployment target is macOS 15; CI uses macOS 26.

Initialize the FFmpeg submodule, then build:

```sh
git submodule update --init --depth 1
make
```

`FFmpeg/` is pinned to the official FFmpeg `n9.0` release tag. Override
`FFMPEG_SOURCE` only when intentionally building against another source tree.
The build caches FFmpeg configuration using its revision, source changes,
deployment target, and enabled flags. Keep format-reader headers in the
Makefile dependencies so changes rebuild the extension and test executable.

`make` creates an ad-hoc-signed development bundle in
`build/FFmpeg Media Extension.app` without changing the installed app.

## Development signing and installation

Sign in to an eligible Apple Developer account in Xcode. Set `TEAM_ID` to your
Apple Developer team when provisioning, signing, or installing:

```sh
make register TEAM_ID=YOUR_TEAM_ID
```

This obtains development provisioning profiles through Xcode, signs the app
and both extensions, installs the app in `/Applications`, opens the host,
and registers the extensions. The extensions require separate explicit
profiles authorizing their MediaExtension entitlements. Signing uses the
entitlements generated by Xcode.

For individual steps:

```sh
make sign TEAM_ID=YOUR_TEAM_ID SIGN_IDENTITY="Apple Development"
make install TEAM_ID=YOUR_TEAM_ID SIGN_IDENTITY="Apple Development"
make uninstall
```

`make install` also signs the bundle; `make register` adds host launch and
extension registration. Enable Media Extensions in System Settings as described
in the README. **Quit and reopen QuickTime after every installed build**:
a running instance can retain the previous extension process.

When working through a sandboxed development tool, run Apple builds, signing,
installation, registration, process inspection, and system-log diagnostics
outside its sandbox. Sandboxed keychain or signature failures are inconclusive;
repeat read-only checks with normal system access before diagnosing them.

## Tests

Run synthetic reader regressions without installing the app:

```sh
make reader-test
```

These cover asset lifetime, laced-packet identity, cursor movement, concurrent
compaction, and compressed/PCM ranges spanning multiple index windows. Test the
reader directly against local media, including subtitle isolation, tail
recovery, and I/O-error propagation:

```sh
build/reader-tests /path/to/videos
```

Run the signed installation and functional media matrix:

```sh
make test TEAM_ID=YOUR_TEAM_ID MEDIA_DIR=/path/to/videos
```

`MEDIA_DIR` defaults to `$HOME/Movies`. Set `SHARE_MEDIA_DIR` to test files
directly from a mounted share. The matrix discovers `.mkv` and `.webm` files
and checks startup, 60-second and tail seeks, decoded images, and 240-second
read windows. Short clips are read through their explicit end; longer clips
cross the index-compaction boundary. The probe rejects failures that occur
after some buffers have already been returned.

To test an already installed build without reinstalling:

```sh
make build/media-probe
bash Tests/run.sh "/Applications/FFmpeg Media Extension.app"
FME_LOCAL_MEDIA_DIR=/path/to/videos bash Tests/integration.sh build/media-probe
```

For this direct script invocation, use `FME_SHARE_MEDIA_DIR` for mounted-share
fixtures. Keep private media filenames out of committed documentation and tests.

Before accepting a playback change, compile with warning checks, verify the
installed signature, run the functional matrix, and check sequential playback
and a distant seek in a fresh QuickTime instance. Include SDR/HDR VP9 and the
supported audio paths. Perform a clean arm64 build when FFmpeg source or
configuration changes. A successful build or image-generation probe alone does
not establish that QuickTime playback works.

## Architecture and media handling

- `FMEFormatReaderFactory` creates a root `FMEAsset` per opened file.
- `FMEAsset` adapts `MEByteSource` to FFmpeg `AVIOContext`, discovers tracks,
  maintains bounded packet windows and independent packet readers, and owns
  audio decoder/resampler state. SRT tracks use separate child assets so subtitle
  scanning and seeking do not reset A/V windows. Subtitle readers use larger,
  bounded I/O buffers to reduce byte-source calls across sparse captions.
- `FMETrackReader` exposes track information and immutable sample snapshots.
- `FMESampleCursor` provides decode/presentation stepping, seeking, dependency
  flags, and compressed or PCM `CMSampleBuffer` delivery.
- `FMEVideoDecoder` decodes VP9 to BGRA for SDR or 10-bit `x420`/`xf20` for HDR.

FFmpeg 9 `libavformat` demuxes Matroska/WebM. Compressed H.264, HEVC, AV1,
MPEG-4 Video, MPEG-2 Video, AAC, AC-3, E-AC-3, Opus, FLAC, and MP3 samples pass
to Core Media. VP9 uses the project FourCC `FVP9` to route through the bundled
`MEVideoDecoder`; changing it to `vp09` can cause rejection before the extension
is consulted.

DTS/DTS-HD and HE-AAC are decoded to native-endian, interleaved signed 16-bit
stereo LPCM in the format reader. Stereo is deliberate: the QuickTime
multichannel renderer caused crackling. Do not restore multichannel output
without testing playback across the DTS fixtures.

Color and HDR metadata is preserved. PQ/HLG VP9 uses 10-bit bi-planar Core Video
buffers with propagating color and HDR attachments.

Embedded SubRip subtitles are exposed as timed text. QuickTime can render them
and apply caption styles, but initially its on/off menu and Inspector can report
them as disabled while they remain visible. Selecting On, then Off hides them;
subsequent toggles work. This initial-selection mismatch is unresolved.
Subtitle first/last-sample discovery and read-ahead can still add startup delay.
Matroska Cues can narrow a tail scan but are not assumed complete: unindexed
subtitles after the final cue must still be found.

### Subtitle selection diagnostics

Inspect legible-track metadata and the asset's subtitle selection group:

```sh
swiftc -O Tests/Selection/main.swift -framework AVFoundation -framework MediaToolbox -o build/selection-probe
build/selection-probe /path/to/movie.mkv
```

Generate small comparison files with a full FFmpeg CLI (including `libx264`)
and Python 3, then run the same diagnostic:

```sh
bash Tests/Selection/fixtures.sh
build/selection-probe build/subtitle-selection-fixtures/grouped.mov build/subtitle-selection-fixtures/ungrouped.mov build/subtitle-selection-fixtures/subtitles.mkv
```

The grouped native MOV exposes one legible option and allows empty selection.
Removing only its alternate-group field makes that group disappear. With the
installed Matroska reader, `AVURLAsset.loadMediaSelectionGroup(for: .legible)`
fails with underlying error `-16505`, despite recognizing the subtitle track
as legible. Supplying language metadata, using text instead of subtitle media
type, and changing the default-enabled flag did not fix that asset query.

**The asset query failure does not prove that QuickTime cannot toggle subtitles.**
QuickTime's runtime logs show automatic selection of the subtitle track followed
by AVKit reporting its selected option as Off; explicit toggles then work. The
player also exposes runtime legible options despite the standalone asset query
failure. Validate the initial menu state, visible captions, and an On → Off → On
cycle in QuickTime before declaring this issue fixed. The timed-text format's
forced-subtitle flags were zero in the reproduction.

### Correctness invariants

- Preserve byte-source read errors as I/O errors. Only a successful zero-byte
  read or the known file boundary means EOF. Free the custom AVIO context and
  its current buffer when closing a demuxer.
- Keep packet/sample windows bounded, including unselected tracks. Expose
  immutable snapshots and invalidate packet-reader/audio state after compaction.
- Retained cursors must recover their own packet after a window reset. Prefer
  file position, stream, and size for packet identity; do not require synthetic
  DTS values to match those from a freshly opened demuxer.
- Honor a non-nil range end cursor for both compressed and PCM delivery. Returning
  only the first packet can stall video or cause audio crackling.
- Reset and warm up stateful audio decoding on nonsequential access. Preserve
  PCM frame granularity and reusable packet payloads.
- Enable exactly one supported video and one audio track, preferring the
  container's default disposition. Do not infer defaults from stream numbers.

## Tagged releases

[The release workflow](.github/workflows/build.yml) builds and validates an
arm64 bundle on macOS 26. Tags use `vMAJOR.MINOR.PATCH`. The release job embeds
Developer ID provisioning profiles, signs with hardened runtime, notarizes,
and staples the app before publishing:

- `ffmpeg-media-extension-macos-arm64.zip` — the ready-to-use app.
- `ffmpeg-media-extension-corresponding-source.tar.xz` — project source, build
  scripts, and the exact pinned FFmpeg source used for the release.

Configure these repository secrets:

| Secret | Value |
| --- | --- |
| `MACOS_CERTIFICATE` | Base64-encoded Developer ID Application certificate and private key exported as a `.p12`. |
| `MACOS_CERTIFICATE_PASSWORD` | Password for that `.p12` file. |
| `FORMAT_READER_PROVISIONING_PROFILE` | Base64-encoded Developer ID profile for `lv.apps.ffmpeg-media-extension.formatreader.mkv`. |
| `VIDEO_DECODER_PROVISIONING_PROFILE` | Base64-encoded Developer ID profile for `lv.apps.ffmpeg-media-extension.videodecoder.vp9`. |
| `APPLE_API_KEY` | Base64-encoded App Store Connect API private key (`.p8`). |
| `APPLE_API_KEY_ID` | API key ID. |
| `APPLE_API_ISSUER_ID` | API issuer ID. |

Both profiles must authorize the required MediaExtension entitlements and match
the signing certificate. Development profiles must not be used for releases.
Keep certificates, private keys, profiles, and generated signing assets out
of Git.
